# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Personal dotfiles for an Arch Linux + Hyprland (Wayland) desktop, synced across multiple machines via Syncthing (see `.stfolder/`). There is no build/test/lint tooling — this is a collection of config files plus a single provisioning script (`install.sh`).

## Commands

- `./install.sh` — full provisioning: installs pacman/AUR packages, symlinks configs into `~/.config`, sets up ly, zsh/oh-my-zsh, GTK, wallpapers/Matugen, fonts, and cursor/icon themes. Idempotent (safe to re-run), but it mutates real system state (systemd services, `/etc/ly/config.ini`, default shell, package installs) — treat it as a real deploy, not a dry run.
- `bash -n install.sh` — syntax-check the script without running it (useful after editing).
- No test suite, linter, or package manager exists in this repo.

## Architecture

### Layout
- `configs/<component>/` — the source of truth for each app's config (hypr, waybar, rofi, foot, kwybars, matugen, ly, swayosd, cursors, fonts, Wallpapers, `.zshrc`).
- `install.sh` — the only executable logic in the repo. All setup knowledge lives here; there's no other entry point.

### Symlink strategy (important)
`install.sh`'s `link_config()` symlinks individual **files**, never whole component directories, from `configs/<component>/` into `~/.config/<component>/`. This is deliberate: several files under `~/.config` are regenerated per-machine by Matugen (color/theme output) and must NOT be symlinked back into the repo, or a color change on one machine would sync via Syncthing and clobber the other machine's theme.

The excluded, per-machine-generated paths are declared in two places that must stay in sync:
- `MATUGEN_GENERATED_FILES` array in `install.sh`
- the corresponding entries in `.gitignore`

Currently: `waybar/colors.css`, `rofi/rofi_theme.rasi`, `kwybars/themes/kwybars_custom.toml`, `swayosd/colors.css`. When adding a new Matugen template/output, add it in both places.

### Matugen theming pipeline
`configs/matugen/config.toml` defines templates that Matugen renders from a wallpaper's color scheme into various apps (waybar, GTK 3/4, kwybars, vicinae, rofi, swayosd, terminal, Firefox/pywalfox, swaync). Each `[templates.X]` entry has an `input_path` (a `.tera`/template file under `configs/matugen/templates/`) and `output_path` (where the rendered file lands on the live system), often with a `post_hook` to reload the affected app. Triggering a new color scheme: `matugen image <wallpaper> -m dark --source-color-index 0` (see `install.sh` and `configs/rofi/selector.sh`).

`configs/rofi/selector.sh` is the interactive wallpaper picker (rofi + thumbnails via `magick`/`convert`) that re-runs Matugen when a new wallpaper is chosen.

### Hyprland config
`configs/hypr/hyprland.lua` uses Hyprland's **Lua** config API (`hl.monitor(...)`, `hl.on(...)`, `hl.exec_cmd(...)`, etc.), not the legacy `hyprland.conf` syntax. It's organized into clearly marked sections (search for `---- SECTION ----` banners): MONITORS, MY PROGRAMS, AUTOSTART, ENVIRONMENT VARIABLES, PERMISSIONS, LOOK AND FEEL, MISC, INPUT, KEYBINDINGS, WINDOWS AND WORKSPACES.

`configs/hypr/hyprmon.lua` is auto-generated by HyprMon (per-machine monitor layout) — comment at top says "Manual changes may be overwritten," don't hand-edit meaningfully.

Two Hyprland plugins are installed via `hyprpm` in `install.sh`: `hyprexpo` and `hypr-dynamic-cursors`.

### Waybar dual-bar toggle
Waybar has two full configs — `config_open`/`style_open.css` (default at startup) and `config_close`/`style_close.css` — swapped by `configs/waybar/toggle.sh`, plus a separate `lyrics`/`lyrics.css` bar always relaunched at the end of that script. When editing waybar behavior, changes usually need to be mirrored across the open/close variants.

### Third-party themes are fetched at install time, not vendored
Cursors (`configs/cursors/Bibata-Modern-Ice`) are vendored in the repo, but the Fluent icon theme is not: `install_fluent_icons()` in `install.sh` clones `vinceliuice/Fluent-icon-theme` into a temp dir, runs its own upstream `install.sh -d ~/.local/share/icons orange` (which produces `Fluent-orange`, `Fluent-orange-light`, and `Fluent-orange-dark` with full apps/mimetypes/devices coverage, not just folders), then deletes the clone — same clone-build-discard pattern as `check_yay()`. Do not reintroduce a hand-picked subset of that theme's SVGs into `configs/` — a partial vendored copy previously shadowed the complete upstream theme (user icon dirs win over `/usr/share/icons` in the GTK lookup path) and caused Nautilus to show missing/generic icons for anything other than folders.

### Package lists live in install.sh
There's no separate package manifest file — `PACMAN_PACKAGES` and `AUR_PACKAGES` arrays at the top of `install.sh` are the full list of system dependencies. Add new required packages there, in the block matching their purpose (the array is grouped with comments by subsystem: compositor, audio, network/bluetooth, hyprland-adjacent utilities, etc.).

### Language
Comments, log messages, and commit messages in this repo are in Spanish. Match that convention when editing `install.sh` or config comments.
